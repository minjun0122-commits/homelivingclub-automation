# 홈리빙클럽 — 1인 스마트스토어 운영 자동화

네이버 스마트스토어 **홈리빙클럽**(위탁판매, 도매 공급처: 오너클랜)을 혼자 운영하면서 만든 도구 모음입니다.
상품 등록 → 주문 감시·발주 안내 → 인스타그램 릴스·유튜브 쇼츠 제작까지, 반복 작업을 코드로 바꿨습니다.

> AI 코딩 도구(Claude Code)와 함께 만들었습니다. 무엇을 만들지, 어떤 규칙을 지킬지, 결과를 보고 무엇을 바꿀지는 직접 정했습니다.

---

## 한눈에 보기

| 영역 | 하는 일 | 파일 |
|---|---|---|
| 상품 등록 | YAML 한 장 → 검사 → 네이버 커머스 API로 등록 (전시중지 상태로) | `register.py`, `products/*.yaml`, `store_defaults.yaml` |
| 주문 감시 | 10분마다 새 결제 주문 확인 → 텔레그램 알림 + 오너클랜 발주 내용 안내 | `order_watch.py`, `order_watch_hidden.vbs` |
| 릴스 제작 | 촬영 없이 코드로 1080×1920 영상 생성, 배경음악도 직접 합성 → 인스타·쇼츠 동시 게시 | `reels/` |
| 성과 기록 | 게시물별 조회·평균 재생 시간·저장을 CSV로 누적해 포맷 비교 | `reels/stats.csv` |
| 작업 규칙 | Claude Code 훅·스킬·검수 에이전트로 비밀값 보호와 게시 전 검사를 자동화 | `.claude/` |

```
products/*.yaml ─┐
store_defaults ──┴─▶ register.py ──check──▶ 검사 리포트 (네이버에 안 보냄)
                                  └─upload─▶ 이미지 업로드 → 상품 등록 (전시중지)

작업 스케줄러 (10분) ─▶ order_watch.py ─▶ 커머스 API 주문 조회 ─▶ 텔레그램
                                         └─ products/*.yaml 의 order_rule ─▶ "오너클랜에 ○○ 옵션 3개 발주"

reels/<주제>/render.py ─▶ Pillow 로 프레임 그림 ─▶ ffmpeg 인코딩 ─▶ bgm.py 피아노 합성 ─▶ mp4
```

## 1. 상품 등록 (`register.py`)

상품 정보를 YAML에 적고 `check`로 미리 검사한 뒤 `upload`로 등록합니다.

```bash
python register.py check  products/고양이바디필로우.yaml   # 드라이런: 검사 + 미리보기
python register.py upload products/고양이바디필로우.yaml   # 실제 등록 (전시중지 상태)
python register.py list | fetch <번호> | categories <키워드> | display <번호> on|off
```

**실수를 막는 검사 규칙** (하나라도 걸리면 등록 차단)
- 안 채운 `TODO` 항목, 상품정보제공고시에 "추정" 같은 불확실한 표현
- 이미 등록된 상품 중복 등록 (`already_registered: true`)
- 모든 옵션 재고 0, 이미지 파일 누락, 상품명 100자 초과, 태그 10개 초과
- 경고: 마진율 20% 미만, 상품명 50자 초과, '인형' 키워드인데 KC 인증 확인 안 됨

**설계 포인트**
- 배송비·반품지·A/S 같은 공통값은 `store_defaults.yaml` 한 곳에 두고 상품 YAML이 덮어쓰는 구조
- 무조건 **전시중지** 상태로 올려서, 판매자센터에서 눈으로 확인한 뒤에만 공개
- 두 공급사 상품을 묶은 세트(화병 + 튤립)도 `order_rule`로 발주 방법을 함께 기록
- 기존 상품 수정은 `modify_product()` 하나로: 현재 정보 백업 → 필요한 칸만 변경 → 저장 → **실제로 바뀐 항목만 출력**.
  네이버 자동완성 검색어를 보고 상품명을 다듬거나 빠진 태그를 채울 때 사용 (등록 불가 태그는 API 오류 메시지로 걸러냄)

## 2. 주문 감시 (`order_watch.py`)

- 윈도우 작업 스케줄러가 10분마다 창 없이 실행 (`order_watch_hidden.vbs`)
- 새 결제완료 주문 → 텔레그램으로 주문 내용 + **오너클랜에 무엇을 몇 개 발주할지** 안내
- 이미 알린 주문은 상태 파일로 기억해서 중복 알림 없음, `--since 24`로 최근 주문 재확인
- 커머스 API는 등록된 IP에서만 동작 → 공인 IP가 바뀌면 오류 알림에 원인 힌트 포함 (3시간에 1번만)

## 3. 릴스 제작 (`reels/`)

촬영·AI 이미지 없이, 그림과 글자를 코드로 그려 영상을 만듭니다.

- `common.py`, `ratio/render.py` — 캔버스, 글꼴, 체크/엑스 표시, 사진 카드, 등장 애니메이션 등 공통 디자인
- `shampoo/bgm.py` — numpy로 피아노·마림바 아르페지오 + 패드 + 간단한 리버브를 합성 (저작권 걱정 없는 BGM).
  스타일 4종을 순서대로 돌려 쓰고 코드 진행도 매번 바꿔서 "항상 같은 음악" 느낌을 없앰
- `<주제>/render.py` — 장면 함수 목록 `[(초, 함수)]` → 프레임 렌더 → ffmpeg 인코딩 → BGM 합치기
- 상품 사진은 배경을 지워 실제 cm 비율에 맞춰 배치 (예: 90cm 바디필로우 vs 30cm 자·책상·침대)
- 최근 포맷: 7.5초 **한 장면 연속 애니메이션**(`shower/`)과 **4지선다 퀴즈**(`mwquiz/`, `soakquiz/`, `vasequiz/`) —
  첫 프레임부터 핵심 그림이 보이고, 카운트다운 → 정답 공개 → 댓글 질문으로 끝까지 보게 만드는 구조

**지킨 원칙**
- 효능 표현 금지 (예: 샴푸 브러시에 탈모·두피 건강 언급 안 함), 자사 상품은 영상·캡션에 명시
- 실제로 쓰지 않은 사용 후기처럼 보이게 만들지 않기

## 4. Claude Code 작업 환경 (`.claude/`)

AI 도구에 일을 맡길 때 지켜야 할 규칙을 "부탁"이 아니라 설정으로 강제했습니다.

| 종류 | 파일 | 하는 일 |
|---|---|---|
| 훅 (도구 실행 전) | `hooks/guard.py env` | API 키가 든 비밀값 파일을 읽거나 출력하려는 모든 명령을 차단 |
| 훅 (파일 수정 후) | `hooks/guard.py yaml` | 상품 YAML을 고치면 `register.py check`를 자동 실행해 문제를 바로 알려줌 |
| 스킬 | `skills/reel/` | `/reel` 한 번으로 주제 선정 → 스크립트 작성 → 미리보기 확인 → 렌더 → 캡션까지, 업로드 직전에 멈춤 |
| 스킬 | `skills/stats/` | `/stats`로 Meta Business Suite 수치를 `stats.csv`에 누적하고 최신 vs 직전 3개를 비교 |
| 에이전트 | `agents/caption-checker.md` | 게시 전 캡션·영상 문구 검수: 효능 표현, 자사 상품 표기, 가짜 1인칭 후기, 영상 속 이모지 |

## 결과와 배운 점 (2026년 10월, 운영 3주차)

인스타그램 계정을 새로 만들어 하루 1개씩 올리며 포맷을 실험했고, 10/19부터 같은 영상을 유튜브 쇼츠에도 올렸습니다.

**1단계 — 무엇이 추천되는가 (조회수)**

| 포맷 | 예시 | 조회수 | 팔로워 아닌 사람 비율 |
|---|---|---|---|
| 상품 정보형 | 옷걸이 두께, 냉장고 60%, 발매트 비교 | 38 ~ 49 | — |
| 공감형 (1인칭) | 머리 감을 때 하던 것 3가지, 냉장고 열면 나오는 것 | 139 ~ 149 | 96 ~ 98% |
| 구매자 전용 정보 | 바디필로우 실제 크기, 우리 상품 단점 | 8 ~ 36 | 22 ~ 83% |
| 생활 문제형 | 집 냄새 원인, 옷장 뒤 벽, 전자레인지 천장 | 111 ~ 167 | 97 ~ 98% |

- **"누구나 겪는 상황"이면 처음 보는 사람에게 추천이 됩니다.** 사려는 사람만 궁금한 정보(사이즈, 단점)는 거의 퍼지지 않았습니다.
- 조회수가 8까지 떨어졌을 때 계정 상태(도달 범위 제한)부터 확인 → 제한 없음 → 원인을 콘텐츠로 좁혔습니다.

**2단계 — 얼마나 보는가 (평균 재생 시간)**

- 13초짜리든 7.5초짜리든 평균 재생이 **2~3초**로 같았습니다 → 길이가 아니라 첫 장면에서 다음 장면으로 넘어가는 순간에 이탈한다고 판단.
- 장면 전환을 없앤 **한 장면 연속 애니메이션**(샤워기 3초)과 **퀴즈형**(4초)으로 바꾸자 처음으로 2초 벽을 넘었습니다.
- 주제·길이·BGM·게시 시간을 바꿔도 조회 86~167에서 벗어나지 못한 것은 "그림+글자" 형식 자체의 한계로 기록했습니다.

**3단계 — 플랫폼 비교 (같은 영상)**

| 영상 | 인스타 조회 | 쇼츠 조회 |
|---|---|---|
| 샤워기 헤드 (한 장면) | 132 | 1,221 |
| 전자레인지 퀴즈 | 149 | 1,116 |
| 옛 형식 4개 | 120 ~ 167 | 2 ~ 42 |

- 새 형식은 쇼츠에서 인스타의 약 8배가 나왔고, 옛 형식은 쇼츠에서 거의 추천되지 않았습니다. 쇼츠 조회의 98%가 쇼츠 피드(알고리즘 추천)에서 나왔습니다.

**4단계 — 판매로 이어지는가 (아직 아님)**

- 스마트스토어 유입 분석: 최근 방문 15건, 주문 0건. 인스타·유튜브 유입은 상위 경로에 없었습니다.
- 원인: 영상에 상품이 없고, 쇼츠에서 스토어로 가는 링크도 없었음 → 유튜브 채널 첫 링크를 스토어로 바꾸고, 상품의 실제 특징을 정답으로 쓰는 **상품 퀴즈**를 3개 중 1개 비율로 섞는 실험을 시작했습니다.
- 동시에 네이버 검색 노출 개선: 태그가 하나도 없던 상품을 발견해 채우고, 자동완성 검색어에 맞춰 상품명 3개를 수정했습니다.

---|---|---|---|
| 상품 정보형 | 옷걸이 두께, 냉장고 60%, 발매트 비교 | 38 ~ 49 | — |
| 공감형 (1인칭) | 머리 감을 때 하던 것 3가지, 냉장고 열면 나오는 것 | 139 ~ 149 | 96 ~ 98% |
| 구매자 전용 정보 | 바디필로우 실제 크기, 우리 상품 단점 | 8 ~ 36 | 22 ~ 83% |
| 생활 문제형 | 집 냄새 원인, 10월에 해둘 것 | 111 ~ 123 | 98% |

- **"누구나 겪는 상황"이면 처음 보는 사람에게 추천이 됩니다.** 사려는 사람만 궁금한 정보(사이즈, 단점)는 기존 팔로워 밖으로 거의 퍼지지 않았습니다.
- 조회수가 갑자기 8까지 떨어졌을 때 계정 상태(도달 범위 제한)부터 확인 → 제한 없음 → 원인을 콘텐츠로 좁혔습니다.
- **남은 문제: 저장·댓글 거의 0.** 첫 화면을 '목록'에서 '질문 하나 + 큰 그림'으로 바꾸고 13초로 줄인 포맷이 조회 115~154로 가장 안정적이라, 이 포맷을 유지하며 참여를 늘리는 실험을 진행 중입니다.
- 스토어 주문은 아직 0건입니다. 인스타 → 스토어 유입보다 네이버 검색 노출(상품명·태그·가격 경쟁력)이 먼저라는 점을 다음 과제로 두고 있습니다.

## 실행 방법

```bash
pip install -r requirements.txt
cp .env.example .env    # 커머스 API ID/시크릿, 텔레그램 봇 토큰 입력
python register.py auth
```

- 상품 사진(`products/images/`), 글꼴(`reels/fonts/`), 결과 영상, 주문 기록·백업(`output/`), 개인 설정(`.claude/settings.local.json`)은 저작권·개인정보 때문에 저장소에 넣지 않았습니다.
  릴스 스크립트는 해당 이미지와 Pretendard 글꼴이 있어야 실행됩니다.
- 상품 YAML은 예시 2개만 포함했고, 연락처는 가렸습니다.
