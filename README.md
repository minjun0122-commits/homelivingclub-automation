# 홈리빙클럽 — 1인 스마트스토어 운영 자동화

네이버 스마트스토어 **홈리빙클럽**(위탁판매, 도매 공급처: 오너클랜)을 혼자 운영하면서 만든 도구 모음입니다.
상품 등록 → 주문 감시·발주 안내 → 인스타그램 릴스 제작까지, 반복 작업을 코드로 바꿨습니다.

> AI 코딩 도구(Claude Code)와 함께 만들었습니다. 무엇을 만들지, 어떤 규칙을 지킬지, 결과를 보고 무엇을 바꿀지는 직접 정했습니다.

---

## 한눈에 보기

| 영역 | 하는 일 | 파일 |
|---|---|---|
| 상품 등록 | YAML 한 장 → 검사 → 네이버 커머스 API로 등록 (전시중지 상태로) | `register.py`, `products/*.yaml`, `store_defaults.yaml` |
| 주문 감시 | 10분마다 새 결제 주문 확인 → 텔레그램 알림 + 오너클랜 발주 내용 안내 | `order_watch.py`, `order_watch_hidden.vbs` |
| 릴스 제작 | 촬영 없이 코드로 1080×1920 영상 생성, 배경음악도 직접 합성 | `reels/` |

```
products/*.yaml ─┐
store_defaults ──┴─▶ register.py ──check──▶ 검사 리포트 (네이버에 안 보냄)
                                  └─upload─▶ 이미지 업로드 → 상품 등록 (전시중지)

작업 스케줄러 (10분) ─▶ order_watch.py ─▶ 커머스 API 주문 조회 ─▶ 텔레그램
                                         └─ products/*.yaml 의 order_rule ─▶ "오너클랜에 ○○ 옵션 3개 발주"

reels/<주제>/render.py ─▶ Pillow 로 프레임 그림 ─▶ ffmpeg 인코딩 ─▶ bgm.py 피아노 합성 ─▶ mp4
```

---

## 1. 상품 등록 (`register.py`)

상품 정보를 YAML에 적고 `check`로 미리 검사한 뒤 `upload`로 등록합니다.

```bash
python register.py check  products/고양이바디필로우.yaml   # 드라이런: 검사 + 미리보기
python register.py upload products/고양이바디필로우.yaml   # 실제 등록 (전시중지 상태)
python register.py list | fetch <번호> | categories <키워드> | display <번호> on|off
```

**실수를 막는 검사 규칙** (하나라도 걸리면 등록 차단)
- 안 채운 `TODO` 항목, 상품정보제공고시에 "추정" 같은 불확실한 표현
- 이미 등록된 상품 중복 등록 (`already_registered: true`)
- 모든 옵션 재고 0, 이미지 파일 누락, 상품명 100자 초과, 태그 10개 초과
- 경고: 마진율 20% 미만, 상품명 50자 초과, '인형' 키워드인데 KC 인증 확인 안 됨

**설계 포인트**
- 배송비·반품지·A/S 같은 공통값은 `store_defaults.yaml` 한 곳에 두고 상품 YAML이 덮어쓰는 구조
- 무조건 **전시중지** 상태로 올려서, 판매자센터에서 눈으로 확인한 뒤에만 공개
- 두 공급사 상품을 묶은 세트(화병 + 튤립)도 `order_rule`로 발주 방법을 함께 기록

## 2. 주문 감시 (`order_watch.py`)

- 윈도우 작업 스케줄러가 10분마다 창 없이 실행 (`order_watch_hidden.vbs`)
- 새 결제완료 주문 → 텔레그램으로 주문 내용 + **오너클랜에 무엇을 몇 개 발주할지** 안내
- 이미 알린 주문은 상태 파일로 기억해서 중복 알림 없음, `--since 24`로 최근 주문 재확인
- 커머스 API는 등록된 IP에서만 동작 → 공인 IP가 바뀌면 오류 알림에 원인 힌트 포함 (3시간에 1번만)

## 3. 릴스 제작 (`reels/`)

촬영·AI 이미지 없이, 그림과 글자를 코드로 그려 영상을 만듭니다.

- `common.py`, `ratio/render.py` — 캔버스, 글꼴, 체크/엑스 표시, 사진 카드, 등장 애니메이션 등 공통 디자인
- `shampoo/bgm.py` — numpy로 피아노 아르페지오 + 패드 + 간단한 리버브를 합성 (저작권 걱정 없는 BGM)
- `<주제>/render.py` — 장면 함수 목록 `[(초, 함수)]` → 프레임 렌더 → ffmpeg 인코딩 → BGM 합치기
- 상품 사진은 배경을 지워 실제 cm 비율에 맞춰 배치 (예: 90cm 바디필로우 vs 30cm 자·책상·침대)

**지킨 원칙**
- 효능 표현 금지 (예: 샴푸 브러시에 탈모·두피 건강 언급 안 함), 자사 상품은 영상·캡션에 명시
- 실제로 쓰지 않은 사용 후기처럼 보이게 만들지 않기

## 결과와 배운 점 (2026년 10월, 운영 2주차)

인스타그램 계정을 새로 만들어 하루 1개씩 올리며 포맷을 실험했습니다. (팔로워 0 → 4명)

| 포맷 | 예시 | 조회수 | 팔로워 아닌 사람 비율 |
|---|---|---|---|
| 상품 정보형 | 옷걸이 두께, 냉장고 60%, 발매트 비교 | 38 ~ 49 | — |
| 공감형 (1인칭) | 머리 감을 때 하던 것 3가지, 냉장고 열면 나오는 것 | 139 ~ 149 | 96 ~ 98% |
| 구매자 전용 정보 | 바디필로우 실제 크기, 우리 상품 단점 | 8 ~ 36 | 22 ~ 83% |
| 생활 문제형 | 집 냄새 원인, 10월에 해둘 것 | 111 ~ 123 | 98% |

- **"누구나 겪는 상황"이면 처음 보는 사람에게 추천이 됩니다.** 사려는 사람만 궁금한 정보(사이즈, 단점)는 기존 팔로워 밖으로 거의 퍼지지 않았습니다.
- 조회수가 갑자기 8까지 떨어졌을 때 계정 상태(도달 범위 제한)부터 확인 → 제한 없음 → 원인을 콘텐츠로 좁혔습니다.
- **남은 문제: 평균 시청 2초, 저장·댓글 거의 0.** 첫 화면을 '목록'에서 '질문 하나 + 큰 그림'으로 바꾸고 13초로 줄이는 실험을 진행 중입니다.
- 스토어 주문은 아직 0건입니다. 인스타 → 스토어 유입보다 네이버 검색 노출(상품명·태그·가격 경쟁력)이 먼저라는 점을 다음 과제로 두고 있습니다.

## 실행 방법

```bash
pip install -r requirements.txt
cp .env.example .env    # 커머스 API ID/시크릿, 텔레그램 봇 토큰 입력
python register.py auth
```

- 상품 사진(`products/images/`), 글꼴(`reels/fonts/`), 결과 영상, 주문 기록(`output/`)은 저작권·개인정보 때문에 저장소에 넣지 않았습니다.
  릴스 스크립트는 해당 이미지와 Pretendard 글꼴이 있어야 실행됩니다.
- 상품 YAML은 예시 2개만 포함했고, 연락처는 가렸습니다.
